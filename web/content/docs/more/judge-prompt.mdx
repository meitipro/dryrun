## What the validators are never told

The prompt carries the rules and one scenario and nothing else. It does not say what the author expected, who wrote the scenario, who owns the rules, what the stake or the bounty is, or whether the suite is green. It never asks whether the rules are good: it asks what they say, and it forbids adding rules or common sense that is not written there.

## How validators agree

The leader asks its model and returns one string, the label: ALLOW, BLOCK or UNCLEAR. Each validator asks its own model the same prompt and agrees only when its own label is exactly the leader's. Nothing else is compared and nothing else is stored from the model: no reason, no quoted rule number.

The case result and the suite colour are then computed in contract code from the label and the author's expectation, so GREEN always means the same thing, never the model's opinion.

An answer that cannot be read (not JSON, or a label outside the three) is retried once, then fails the round. It never becomes a label, because defaulting to ALLOW would pass a case nobody read and defaulting to UNCLEAR would pay a bounty for it.
